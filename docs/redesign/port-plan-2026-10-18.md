# Port plan: the Appmilla Factory look, onto the dashboard as Part A left it

Written 18 October 2026, for the builders of stages 1 to 3 of the redesign. It was checked against
Part A's branch (`part-a-build`, last read at `6ee5f0a`) and Part D's branch (`part-d`, at
`8ad3f37`). Re-check any name marked "Part D" once that branch lands, because it is still moving.

The approved design is kept outside this repository, in the design hand-over folder. References
below such as `review/now.html` or `components/bundle.css` point into that folder. The design's
pages use example projects and figures. None of them may be copied into this repository.

## 0. Ground rules for every stage

- **The existing class names in `style.css` stay in the templates.** They take the look of the
  design class listed beside them. Where there is no existing name, add the new name given here.
  New names follow the house style (plain BEM, no `am-` prefix), so the stylesheet keeps one naming
  scheme.
- **Port a design rule by copying its declarations from `components/bundle.css` onto the mapped
  selector.** Every value in that sheet is already a token. Do not paste the `am-*` selectors
  themselves.
- **Templates render and the query layer computes.** If a design element needs a figure that the
  view model does not carry, leave it out or show the honest gap ("Not measured", "No baseline
  yet"). Never work out a new figure in a template, and never show a zero, a dash in place of a
  zero, or an example figure. Counting rows that the page already shows (`| length` on a list the view
  passes) is allowed: it is the same data, not a new figure. The few template-side mappings this plan allows are listed in
  section 6, item 9.
- **Keep the `data-panel` attributes and the `id="panel-…"` ids on every fragment exactly as they
  are**, and keep the fragments in the same order on the Now page (section 6, item 2).

## 2. Tokens plan

### 2a. New custom properties

Copy `review/tokens.css` in full into the top of `style.css`:
- the light block on `:root, [data-theme="light"]`;
- the dark block on `[data-theme="dark"]`;
- the spacing, radius, layout and font block on `:root`.

The attribute selectors work on any element, so `data-theme="dark"` on one section (the Needs-you
band, the sign-in brand panel) re-resolves every token inside it.

The new names are:
- **Colour:** `--deep-green`, `--bright-green`, `--accent-text`, `--luminous`, `--bg`, `--surface`,
  `--surface-sunken`, `--topbar`, `--kicker`, `--line`, `--line-strong`, `--heading`, `--text`,
  `--text-dim`, `--on-dark`, `--on-dark-dim`, `--on-dark-accent`, `--focus`, `--tint-green`,
  `--tint-green-strong`, `--tint-neutral`.
- **Status:** `--status-done`, `--status-risk`, `--status-fail`, `--status-wait` and
  `--status-info`. Each has a `-text` partner, and all but `--status-done` have a `-tint` partner.
- **Shadows:** `--shadow-card`, `--shadow-raised`.
- **Spacing:** `--space-4` up to `--space-64`.
- **Radius:** `--radius-sm`, `--radius-md`, `--radius-lg`, `--radius-pill`.
- **Layout:** `--content-max`, `--topbar-height`, `--accent-bar`.
- **Fonts:** `--font-heading`, `--font-body`, `--font-mono`.

`@font-face` rules go straight after the tokens, one per file in `frontend/static/fonts/`:
- Urbanist 600 and 700;
- Public Sans 300, 400, 500, 600 and 700.

Each rule uses `url("/static/fonts/<file>.woff2") format("woff2")` and `font-display: swap`. The
paths are root-relative, which keeps them free of `http`.

### 2c. Contrast rules from the design (put them in the contract comment)

- **Bright Green `--bright-green` (#3F8C43) is never text on the light page.** It is 3.8:1. Use it
  for bars, stripes, step dots, progress and icons. Green words (eyebrows, links) use
  `--accent-text`.
- **Status colours (`--status-*`) are for dots, bars and icons only.** Words in pills, badges and
  stage times use `--status-*-text` on the matching tint.
- **Luminous Green `--luminous` is text only on Deep Green.** That means the Needs-you band, a
  key tile or the kicker band. On a light ground it may only be a fill or a bar. Use it once per
  screen.
- **`--line` (#E4E7E4) is decoration only.** Control borders, dashed outlines and the hatch edge
  use `--line-strong`, at 3:1 or better.
- **Waiting is purple (`--status-wait`), never amber or red.** It becomes a fault only when it is
  old, and then the age says so.
- In dark mode, eyebrows and links use `--accent-text`. That token is already redefined to
  #5FD98C there.

### 4e. The theme switch script, `frontend/static/theme.js` (NEW)

A first-party static file. `test_no_cdn_references` already sweeps it. About 25 lines, all inside
an IIFE:

```
(function () {
  "use strict";
  var KEY = "factory-theme";
  function stored() { try { return localStorage.getItem(KEY); } catch (e) { return null; } }
  function store(v) { try { localStorage.setItem(KEY, v); } catch (e) { /* private mode */ } }
  function system() {
    try { return window.matchMedia("(prefers-color-scheme: dark)").matches ? "dark" : "light"; }
    catch (e) { return "light"; }
  }
  var root = document.documentElement;
  var t = stored(); if (t !== "dark" && t !== "light") t = system();
  root.setAttribute("data-theme", t);
  document.addEventListener("DOMContentLoaded", function () {
    document.querySelectorAll(".theme-switch").forEach(function (b) {
      sync(b);
      b.addEventListener("click", function () {
        var next = root.getAttribute("data-theme") === "dark" ? "light" : "dark";
        root.setAttribute("data-theme", next); store(next);
        document.querySelectorAll(".theme-switch").forEach(sync);
      });
    });
    document.querySelectorAll("[data-print]").forEach(function (b) {
      b.addEventListener("click", function () { window.print(); });
    });
  });
  function sync(b) {
    var dark = root.getAttribute("data-theme") === "dark";
    b.setAttribute("aria-pressed", dark ? "true" : "false");
    var l = b.querySelector(".theme-switch__label"); if (l) l.textContent = dark ? "Light mode" : "Dark mode";
  }
})();
```

Include it in `base.html`, `client_base.html` and `login.html`. `reports_export.html` gets it
through `base.html`. Do not write the word "returns" into it: harmless here, but the habit
matters for the client templates.

**As built in stage 1 (18 October 2026): the switch has no `aria-pressed`.** The sketch above
pairs `aria-pressed="true"` with the words "Light mode", which a screen reader announces as "Light
mode, pressed": that sounds like light mode is on when the page is dark. So the button's words
name the theme it switches to ("Dark mode" on a light page, "Light mode" on a dark one), with a
visually hidden "Switch to" in front, and no pressed state. The button starts `hidden` and
`theme.js` shows it, because it does nothing without the script. On phones the word "mode" is
hidden so the top bar fits.

## 6. Risks

1. **The exact attribute order in the journey bar.** `test_pages.py` asserts the literal
   `journey-station--current" title="merge decision"`. The macro must keep
   `class="journey-station journey-station--{{ st.glyph_state }}" title="{{ st.name }}"`. Put any
   new class *before* the modifier, never after it, and never between the class and the title.
2. **The fragment order on Now.** A test slices the page between `data-panel="p4"` and
   `data-panel="p2"`, and between `p2` and `p3`. So the Needs-you band (p4) must come before In
   progress (p2), and In progress before Recent activity (p3). The hero block keeps p4 first.
3. **Fragments are swapped whole.** `sse.js` replaces each `[data-panel]` element's outer HTML
   with `/fragments/{panel}`, which renders the fragment template alone. So:
   - the hero look must live on the fragment's own root, `section.needs-you.panel-card--hero` with
     `data-theme="dark"`, not on a wrapper in `home.html`;
   - every fragment must keep importing `macros.html` itself.
4. **Code chips and brackets.** `test_titles_lead_and_codes_follow` looks for `(FEAT-0001)` with
   brackets, and another test counts `(FEAT-000A)`. Dropping the brackets for the design's chip
   needs both assertions changed to the chip markup, in the same commit.
5. **Rows stay table rows on the Features page.** `test_a_cancelled_feature_is_not_called_on_track`
   slices a Features row to its `</tr>`. Keep `feature_table` as a `<table>`. The new
   `feature_rows` list is for Now only.
6. **"Decide in Slack" has no link.** The read model carries no Slack thread address. Render
   `decide-in-slack` as plain text in the Slack style, not as `<a href="#">`. A dead link would
   look like an action that does nothing. When an address arrives, it becomes a link.
7. **`sse.js` still looks for the old banner name.** It checks `.banner--projector_stalled`, so it
   can add the paused banner beside the server's stale banner. The fix is one line
   (`banner--projector_stalled` becomes `banner--stale`), plus the plain wording in section 5.
   Part A and Part D have both edited `sse.js` today, and a node test covers it. So the fix goes to
   whoever lands last, not to a redesign stage.
8. **The CDN fence.** `test_no_cdn_references` fails on `http://` or `https://`:
   - in any `.html` under `frontend/`, including `icon_sprite.html` and new partials;
   - in top-level `frontend/static/*.js` and `*.css`.

   So:
   - inline SVG gets no `xmlns` attribute (its value is a web address);
   - font URLs are root-relative;
   - the `Prepared by Appmilla · appmilla.com` style line is plain text, never a link with a
     scheme.

   The logos are PNG, so no SVG file needs a namespace. The OFL licence texts in
   `static/fonts/` contain `https://` and must stay. Any new test that sweeps `static/**` must
   leave out `*-OFL.txt`, and should check that each `.woff2` starts with the `wOF2` signature.
9. **Template-side mappings this plan allows,** each a display choice, never a new figure:
   - **band to pill class:** G gives ok, A gives risk, R gives fail, and — gives the not-measured
     look;
   - **severity bands:** low, moderate and serious use the same classes. An issue whose `kind`
     starts with "Waiting" uses `status-pill--wait` instead, because waiting is purple;
   - **the waiting step:** the stepper shows the current station as waiting

   The last two read display strings. Ask the Part B/D/E session for a `waiting` glyph state and
   an `open` flag on `WaitRow`, and switch over when they land. Do not add other inferences.
10. **Client fences.** `test_client_templates_reference_no_operator_only_fields` greps
    `client_base.html` and `client_home.html` for `coach_score|coach-score|turns|agent_id|evidence`
    as substrings, so "returns" or "evidence-based" would fail. A client page must not contain
    "Fleet", "Issues", "A-8" or "IN-4" anywhere in its HTML. Do not show `chrome`, costs, other
    tenants or machinery on client pages.
11. **Export fences.** `test_export_template_is_clean_of_internal_fields` lower-cases the text of

    - "issue", "error", "turns", "evidence", "in_flight", "correlation_id" and others;

    The test reads only that file. If the document moves into a partial, add the partial to the

    renders the template with a bare Jinja environment and no `nav`, `signed_in` or `chrome`. When
    the export extends `base.html`, check that this still renders, and that the base adds no text

12. **No `|safe` on data.** Autoescaping stays on. The sprite is a template include, not a

13. **Theme on part of the page.** `data-theme="dark"` on the hero and the login brand panel works

14. **The sticky tab bar and the chat toggle** can overlap at narrow widths. Hide the toggle under
